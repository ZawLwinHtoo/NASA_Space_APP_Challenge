## Exact request boundaries

Check-in permits only astronaut_id, hr, sleep, bp, symptoms; output includes id. Unavailable readings may be null or omitted and are stored null. BP is a paired display string such as "120 / 80", or null. radiation, microgravity and other extra telemetry are NOT accepted; extra=forbid returns 422. No telemetry columns or migration were added.

Evaluation requires all three fields: check_in_id (nonempty string), communication_status (online/offline), emergency_override (strict JSON boolean, not a string or number). No client-supplied inventory, baseline or measurement overrides are accepted. No fixture_id field is accepted.

## Response and errors

Success is the exact engine response: status, observations, missing_data, resource_constraints, safety_flags, next_check, requires_medical_officer_review, explanation, evidence_sources, diagnosis. Status vocabulary is needs_review / insufficient_evidence / escalate. Do not translate these into fixture review/resource-unavailable. insufficient_evidence is a valid HTTP 200 response. next_check may be null. Explicit override produces escalate and next_check=null; diagnosis remains null.

404 unknown check-in: {"detail":"Check-in not found"}.
422 invalid input: {"detail":[{"loc":["body","emergency_override"],"msg":"...","type":"..."}]}. Exact validation messages are Pydantic-generated; error details omit input values. Missing fields, unknown extra fields and invalid types all return 422.
503 unavailable engine dependency: {"detail":"Evaluation service unavailable"}. It is not returned for valid abstention or resource constraints.
500 engine/internal persisted-data failure: {"detail":"Evaluation failed"}. Server logs retain exception tracebacks for diagnosis; HTTP messages do not echo inputs. Do not retry 500/503 as though they were a successful medical result.

## Trusted inventory and mappings

SQLite check-in, matching recorded baseline and SQLite inventory are loaded by the backend. hr→resting_hr_bpm, sleep→sleep_hours; null BP→two null readings. Saved recorded_at is UTC receipt time, not invented device acquisition time. Explicit context supplies communication/override.

Allowlist: Blood-pressure monitor→bp_monitor; Digital thermometer or Thermometer→thermometer; Pulse oximeter→pulse_oximeter; Weighing scale→weighing_scale. Only quantity>0 and available=true are usable. The current database lacks a separate usable field, so available is the conservative usability proxy. No expiry is inferred. Unmapped names do not become available engine equipment; ambiguous duplicate canonical IDs fail internally. Final independent usability/expiry schema remains a separate team decision.

## Startup and browser connection

From backend/: .venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000.
Allowed origins are http://127.0.0.1:5173 and http://localhost:5173. Different ports/origins need explicit CORS configuration. localhost on another phone/laptop refers to that device, not this backend. Cross-device testing requires an explicitly agreed LAN bind/address and CORS origin; this implementation does not expose the server on the network automatically.

No internet is needed for core evaluation after dependencies/assets are installed. NASA research C001–C004 data remains separate and has no approved public endpoint. Never submit research labs as synthetic check-ins.
